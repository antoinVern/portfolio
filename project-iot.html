Étape 1

Programmation Arduino — Acquisition et transmission

Le Seeeduino LoRaWAN est programmé avec l'Arduino IDE. Il lit les données du capteur SCD30 via I²C, les compresse dans un payload binaire de 6 octets et les envoie périodiquement vers The Things Network.

1
Lecture du capteur SCD30 (I²C)
Utilisation des bibliothèques AdafruitSensor et SCD30 pour lire les trois mesures. Le capteur est interrogé toutes les 2 secondes.
// Lecture des données SCD30 #include <SparkFun_SCD30_Arduino_Library.h> SCD30 airSensor; void loop() { if (airSensor.dataAvailable()) { uint16_t co2 = airSensor.getCO2(); float temp = airSensor.getTemperature(); float hum = airSensor.getHumidity(); } }
SCD30 opérationnel — 3 grandeurs lues
2
Encodage du payload (6 octets)
Les valeurs flottantes sont converties en entiers (×100 pour la précision) et encodées sur 6 octets dans un tableau binaire avant transmission LoRaWAN, afin de minimiser la taille du paquet et optimiser la durée de vie de la batterie.
// Encodage payload 6 octets uint8_t payload[6]; uint16_t co2_enc = (uint16_t) co2; int16_t temp_enc = (int16_t)(temp * 100); int16_t hum_enc = (int16_t)(hum * 100); payload[0] = co2_enc >> 8; payload[1] = co2_enc & 0xFF; payload[2] = temp_enc >> 8; payload[3] = temp_enc & 0xFF; payload[4] = hum_enc >> 8; payload[5] = hum_enc & 0xFF;
Payload 6 octets optimisé pour LoRaWAN

Étape 2

The Things Network — Décodage du payload

Côté TTN, une fonction JavaScript decodeUplink est déployée pour extraire les valeurs physiques depuis les octets bruts reçus via LoRaWAN.

1
Fonction decodeUplink — TTN Payload Formatter
La fonction "Payload Formatter" sur TTN décode les 6 octets et reconstruit les valeurs de CO₂, température et humidité avec leur précision d'origine.
// Payload Formatter JavaScript — TTN function decodeUplink(input) { var bytes = input.bytes; var co2 = (bytes[0] << 8) | bytes[1]; var temp = ((bytes[2] << 8) | bytes[3]) / 100; var hum = ((bytes[4] << 8) | bytes[5]) / 100; return { data: { co2: co2, temperature: temp, humidity: hum } }; }
Données décodées sur TTN et publiées via MQTT

Étape 3

Node-RED — Traitement, stockage et visualisation

Node-RED souscrit au topic MQTT de TTN, traite les messages JSON et alimente trois sorties en parallèle : un dashboard de jauges, un fichier CSV horodaté et des alertes Telegram.

1
Réception MQTT & formatage
Un nœud MQTT-in se connecte au broker TTN. Un nœud function extrait les champs co2, temperature et humidity du payload JSON.
Flux MQTT opérationnel — données reçues en temps réel
2
Stockage CSV horodaté
Chaque mesure est écrite dans un fichier CSV local avec un horodatage ISO 8601. Ce fichier sert d'historique pour la traçabilité et l'analyse ultérieure des données environnementales.
// Format CSV — une ligne par mesure timestamp,co2_ppm,temperature_c,humidity_pct 2025-04-15T10:32:11Z,812,21.43,58.20 2025-04-15T10:34:11Z,845,21.51,57.95
Historique CSV opérationnel — horodatage automatique
3
Dashboard — Jauges temps réel
Le module node-red-dashboard affiche les trois valeurs sous forme de jauges animées en temps réel. Les seuils min/max des jauges sont configurés pour refléter les plages normales d'un environnement intérieur.
Dashboard jauges opérationnel — actualisation temps réel
4
Alertes Telegram automatiques
Des nœuds function évaluent chaque mesure par rapport à des seuils critiques. Si la valeur dépasse la plage acceptable (ex. : humidité en dehors de 40% – 70%), un message d'alerte est automatiquement envoyé sur un groupe Telegram via un bot.
// Logique de seuil — Node-RED function var hum = msg.payload.humidity; if (hum < 40 || hum > 70) { msg.payload = `⚠️ Alerte humidité : ${hum}% hors plage [40%-70%]`; return msg; // → nœud Telegram } return null; // Pas d'alerte si OK
Alertes Telegram opérationnelles en temps réel

Bilan

Résultats et perspectives

Le projet est une réussite complète : la chaîne IoT de bout en bout est fonctionnelle. La communication LoRaWAN→TTN→MQTT est stable, le traitement Node-RED est opérationnel et les alertes Telegram se déclenchent correctement.

  • LoRaWAN : liaison SCD30 → TTN opérationnelle, payload encodé sur 6 octets
  • Décodage : fonction decodeUplink JavaScript validée côté TTN
  • Visualisation : dashboard Node-RED en temps réel avec jauges CO₂/temp/humidité
  • Stockage : CSV horodaté avec toutes les mesures historiques
  • Alertes : bot Telegram avec seuils configurables fonctionnel
Perspectives d'amélioration
  • Ajout de nouveaux capteurs (luminosité, particules fines PM2.5)
  • Optimisation des flux Node-RED et ajout de persistance base de données (InfluxDB + Grafana)
  • Intégration d'analyses prédictives basées sur l'intelligence artificielle

Analyse réflexive :

💡
Ce que j'ai acquis. Ce projet m'a fait découvrir concrètement les contraintes des réseaux LPWAN — l'optimisation du payload à 6 octets pour minimiser l'occupation spectrale LoRaWAN m'a appris à raisonner en termes de coût de transmission, ce qui est radicalement différent d'une architecture IP classique.
⚡
Principale difficulté. La configuration des clés TTN (AppKey, DevEUI, AppEUI) et la synchronisation OTAA ont été les étapes les plus délicates : un octet inversé dans la configuration suffisait à empêcher toute jointure au réseau, et le débogage sans retour visuel immédiat était frustrant.
🔄
Ce que je ferais différemment. J'aurais remplacé le stockage CSV par une base de données InfluxDB couplée à Grafana dès le départ — cela aurait permis des visualisations historiques plus riches et aurait rendu le projet directement comparable à une architecture de monitoring professionnelle comme celle de ma SAÉ 3.03.
